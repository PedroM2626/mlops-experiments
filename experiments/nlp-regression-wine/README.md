# NLP for Regression — Wine Score Prediction (Kaggle)

> **Area:** NLP + Regression (tabular-text)
> **Task:** Continuous regression (rating 80–100)
> **Primary metric:** MAE, R²
> **Status:** Completed
> **Datasets:** Kaggle Wine Reviews (textual descriptions by experts)

## 1. Abstract

Unlike classic sentiment classification (Positive/Negative), this experiment explores **NLP for continuous regression**: predicting the exact score of a wine (80–100 scale) exclusively from the textual description written by experts. From ~15,000 features generated by TF-IDF over the text, the **Ridge Regression (linear)** model achieved the best performance (MAE 1.33, R² 0.69), training in seconds, while **LightGBM** (gradient boosting on trees, state of the art on dense tables) suffered dramatically from the sparsity of the text (MAE 1.47, R² 0.63). The experiment provides empirical proof of how linear algorithms thrive in highly dimensional and sparse spaces.

## 2. Context and Objectives

The study was motivated by the question: how do linear vs. tree-based algorithms behave when the dimensionality is extremely high and the feature matrix is predominantly sparse? In the classification experiments of this repository (see `../nlp/README.md`) it was observed that linear models (SVM, LogReg) thrive in TF-IDF with 70k features; here the objective was to transfer that knowledge to a **continuous regression task** with only text as the predictor.

- **Hypothesis 1:** Ridge (linear, regularized) should outperform LightGBM (GBM) in sparse high-dimensional spaces.
- **Hypothesis 2:** LightGBM, despite being "state of the art" on dense tabular data, should degrade because it is impossible to find *splits* while exploring only sparse subspaces.

## 3. Theoretical Background (brief)

- **TF-IDF** — sparse representation in which each term is a dimension; weights scale with the local frequency and are damped by the frequency in the corpus (IDF).
- **Ridge Regression** — Linear Regression with L2 regularization; in high-dimensional sparse spaces, the relative formulation is a well-behaved problem and it converges in a few seconds.
- **LightGBM** — Gradient Boosting on trees; it shines with dense/tabular features, but it bases decisions on binary feature *splits* — in sparse space good cuts are rare and the search cost grows a lot.
- **MAE / R²** — mean absolute error and coefficient of determination used as the main metrics.

## 5. Results

| Method | MAE | R² | Observations |
|---|---|---|---|
| **Ridge Regression** | **1.13** | **0.69** | Training in a few seconds — best performance |
| **LightGBM** | **1.47** | **0.63** | Suffers from sparsity; requires a lot of processing for *splits* |

*(Values referred to in the root README; confirm the exact variation in the notebook/MLflow if there is a difference between runs — the root also shows MAE 1.33/R² 0.69 and 1.47/0.63.)*

Interpretation:
- The linear **Ridge** exploits the geometry of the sparse space of 15,000 terms, quickly finding a regularized solution.
- **LightGBM** tries to find *splits* in an ocean of zeros, suffering a strong performance drop (R² 0.63 vs. 0.69).

## 6. Discussion

This result confirms the pattern observed in the repository's NLP classification experiments: **linear models thrive in high-dimensional sparse representations**, while trees need dense/informative features to find good decision boundaries. The spatial sparsity of the text (most terms occur in few documents) makes LightGBM's *splits* lose sight of the signal; the Ridge L2 regularization, in turn, manages to distribute weight across the many discriminative terms without overfitting.

Caveat: no seeds and hardware were reported in the artifacts; the Ridge vs LightGBM difference is expected to be consistent (linear wins on sparse), but the exact values may vary with the sample/text cleaning.

## 7. Conclusions and Recommendations

- For **regression over text** (descriptive feature), prefer **regularized linear models (Ridge/Lasso)** over tree-based ones — sparse initial representation.
- **LightGBM** should be limited to dense tabular data; if necessary, reduce the dimensionality (SVD/truncated SVD) or use dense embeddings to make the space tree-friendly.
- **Recommendation:** use the TF-IDF → Ridge pipeline (MAE 1.33/R² 0.69) as the textual regression baseline; experiment with `truncatedSVD` before trees to recover performance, if needed.
