# Databricks AutoML Forecast — Prophet and DeepAR (imported from the cloud) and Local Equivalent

> **Area:** Time Series
> **Task:** Forecasting (regression) of sales in a time series
> **Primary metric:** RMSE / sMAPE (local equivalent); cloud — to be measured (TBD)
> **Status:** Cloud imported (auto-generated notebooks), local equivalent completed
> **Datasets:** `quantity_sales_transactions` (Delta table in the Databricks workspace); the local equivalent uses synthetic sales.

## 1. Abstract

This folder contains the **import of the forecast notebooks generated by Databricks AutoML** (Prophet and DeepAR) for the `quantity_sales_transactions` table, together with the pipeline scripts (`pre-processing`, `training`, `tuning`), all auto-generated by the platform and exported from the cloud workspace, plus the `download_artifacts.py` script that downloads the runs from the remote MLflow tracking. **Cloud results not documented: TBD (they depend on re-execution in a Serverless cluster).** To make local experimentation possible, the local equivalent `../time_series/databricks-forecast-local-equivalent.ipynb` reproduces Prophet, Prophet+Optuna, SARIMA and ETS on synthetic sales (sMAPE 5,66% with Prophet+Optuna).

## 2. Context and Objectives

The original Databricks notebooks depend on a **paid workspace and on credentials**; they are auto-generated by AutoML (title "auto-generated notebook") and, to reproduce the results, they require Serverless compute and the MLflow experiment `3257488039771013`. The objective of this folder is to **preserve and document what came from the cloud**, while the parallel project builds the **local open-source equivalents** (see `../time_series/databricks-forecast-local-equivalent.ipynb`), with no need for a Spark cluster or for credentials.

## 3. Theoretical Background (brief)

- **Databricks AutoML:** auto-generates training pipelines for Delta tables, from a target and `time_col`/`split_col`, returning importable notebooks and an MLflow experiment with trials.
- **Prophet (Meta):** additive GAM with trend (changepoints) and seasonality (Fourier), adopted by AutoML for simple forecasting.
- **DeepAR:** probabilistic _deep learning_ model (gluonts) for multiple/aggregated series forecasting, used by AutoML when the DataFrame has large groups.
- **Hyperopt + SparkTrials** on Databricks for tuning and **MLflow** for tracking.
- **Local open-source equivalent:** Prophet + Prophet+Optuna + SARIMA + ETS, all runnable on a simple machine.

## 6. Discussion

- **Local:** with complex weekly patterns, Prophet+Optuna wins by a margin over the Prophet baseline; SARIMA and ETS came out less effective, indicating that the day-to-day structure (weekly) favors models able to absorb fixed-period seasonality with flexibility (changepoints).
- **Cloud vs Local:** the exported notebooks are auto-generated and parameterized for the real table (`quantity_sales_transactions`); the local equivalent replaces the need for a workspace, but it operates on a synthetic series — a faithful comparison of metrics would require exporting the table and re-executing both.
- **download_artifacts.py:** uses remote MLflow (`mlflow.set_tracking_uri("databricks")`) against the experiment `3257488039771013`; it depends on a `.env` with credentials — **not commited**. The objective is to download the artifacts of each run for local inspection.

## 7. Conclusions and Recommendations

- Prophet is the best choice for series with clear seasonality (sMAPE 5,66% local).
- Although the cloud notebooks exist in this folder, their correct execution is **TBD** — prefer the local pipeline for analysis and training.
- Use `download_artifacts.py` only with credentials via environment variables; never commit tokens.
- In production, reuse the structure of `nb-preprocessing.py`/`nb-training.py`/`nb-tuning.py` as a pipeline reference (Databricks or local with Spark).
